Responsive &amp; Device Behavior 18 1. Design Philosophy &amp; Principles Donora+ is used under stress. A patient&apos;s family searching for blood at 2 a.m. must be able to navigate the app with shaking hands, in low light, after no sleep. Every design decision must be measured against that reality. Five principles guide every screen. 1.1 Clarity over Cleverness No element should make the user think. Labels are plain language. Buttons say exactly what they do. Information hierarchy is immediate — the most important thing on any screen is visible without scrolling. 1.2 Speed First A seeker posting a request should be able to do so in under 60 seconds from cold-open. No mandatory account creation before seeing available donors. Minimum required fields; optional enrichment later. 1.3 Trust is Earned Visually Verification badges, blood-group chips, and donor classification labels carry weight because they are visually distinct and consistently applied. Users must be able to trust what they read at a glance. 1.4 Accessible by Default Minimum 4.5:1 contrast ratio everywhere. Touch targets of 48 dp minimum. All interactive elements have semantic labels for screen readers. No colour-only information — always paired with an icon or text. 1.5 Mobile-First, Admin-Last The seeker and donor experience is designed for phones first, in portrait orientation, at 360 dp minimum viewport width. The admin panel is web-only and designed for desktop — it is a utility tool, not a consumer product. 2. Brand &amp; Visual Language 2.1 Colour Palette All colours are derived from the Donora+ brand. Dark variants of each colour are used on coloured surfaces to maintain contrast. Screen Specifications — Auth &amp; Onboarding SCR-A01 Splash Screen • / Purpose Displays the Donora+ logo and brand mark while the app checks for a valid auth session. No interaction required. Anatomy Full-screen Crimson background (#C0392B) Centred white water_drop icon at 72 dp + &apos;DONORA+&apos; wordmark in white heading1 Circular progress indicator (white, 24 dp) at vertical centre + 40 dp — appears after 400 ms if check is still running No back button, no navigation bar States Loading: spinner visible after 400 ms delay Auth valid: fades to Home (300 ms fade) No auth: fades to Auth Gate Implementation notes Use a 300 ms cross-fade transition. Never flash the splash for more than 2 s — if auth check exceeds 2 s, proceed to Auth Gate. SCR-A02 Auth Gate • /auth Purpose Entry point for unauthenticated users. Presents two primary actions and a brief value proposition. Anatomy Illustration area (top 40% of screen): abstract SVG of water drops / connected dots, Navy on Cloud background heading1: &apos;Find blood. Give life.&apos; in Navy body: one-sentence app description in Slate Primary button (full-width): &apos;Create Account&apos; — Crimson fill, white text Secondary button (full-width, outlined): &apos;I Already Have an Account&apos; — Navy border, Navy text Bottom caption: &apos;By continuing you agree to our Terms of Service&apos; States Default: both buttons enabled Implementation notes Skip this screen entirely if a valid session is found on splash. SCR-A03 Register • /register Purpose Collects the minimum information needed to create an account. Anatomy Top: back arrow + heading1 &apos;Create Account&apos; Input: Full name Input: Phone number (auto-formatted with Pakistan +92 prefix) OR Email toggle Input: Password (with show/hide toggle) Input: Confirm password Checkbox: &apos;I am registering as a (Seeker / Donor)&apos; — two radio pills Primary button: &apos;Continue&apos; Bottom link: &apos;Already have an account? Log in&apos; States Default: form empty, Continue disabled until all required fields valid Inline validation: shown on field blur, not on keystroke Loading: Continue replaced by spinner + &apos;Creating account…&apos; while API call in flight Error: banner below heading (&apos;Could not create account — phone already registered&apos;) Success: navigates to OTP screen Implementation notes The role selection here sets a default; users can switch roles freely later from Profile. Do not collect blood group or city here — that is onboarding step 2. SCR-A04 OTP Verification • /verify-otp Purpose 6-digit code entry to verify phone number. Anatomy heading1: &apos;Enter the code&apos; body: &apos;We sent a 6-digit code to +92 XXX XXXX XXX&apos; (masked number) 6 individual input boxes in a row — each accepts one digit, auto-advances focus Primary button: &apos;Verify&apos; Link below: &apos;Resend code&apos; — disabled with 60 s countdown, then enabled Link: &apos;Change phone number&apos; — navigates back States Default: empty boxes, Verify disabled Loading: Verify replaced by spinner Error (wrong code): boxes shake animation, red border, caption &apos;Incorrect code — X attempts remaining&apos; Error (expired): full-screen inline message with Resend CTA Success: cross-fade to Onboarding step 1 SCR-A05 Login • /login Purpose Returning user authentication. Anatomy heading1: &apos;Welcome back&apos; Input: Phone / email Input: Password (show/hide toggle) Link: &apos;Forgot password?&apos; — right-aligned below field Primary button: &apos;Log In&apos; Bottom link: &apos;Create an account&apos; States Default: Log In disabled until both fields non-empty Loading: spinner in button Error: banner above button &apos;Incorrect phone or password&apos; Success: navigates to Home SCR-A06 Onboarding (4-step stepper) • /onboarding Purpose Progressive profile completion after first registration. Progress indicator across top. Anatomy Persistent: step indicator (4 pills / dots) at top of screen; current step filled Crimson Step 1 — Role Confirm: large illustrated card for Seeker vs Donor; confirms choice made at register Step 2 — Profile Basics: blood group picker (8 chips: A+, A−, B+, B−, AB+, AB−, O+, O−), city text field with autocomplete, optional profile photo upload Step 3 — Donor Classification (donor role only): two large illustrated option cards: &apos;Volunteer&apos; / &apos;Compensated for travel &amp; time&apos;; brief one-line description under each Step 4 — Health Info (donor role only): hemoglobin level field (numeric, mmol/L or g/dL toggle), short multi-select health disclosure checklist (hypertension, diabetes, recent illness, none of the above) Bottom: &apos;Next&apos; primary button + &apos;Skip for now&apos; text link (only for optional steps) Back arrow navigates to previous step; tapping step pills is disabled States Validation: blood group required before Next on step 2; checklist requires at least one option on step 4 Skip on step 4 is allowed — data can be completed later from Profile Implementation notes Seeker users only see steps 1 and 2; steps 3 and 4 are donor-only. After onboarding, donors are directed to the Verification screen; seekers go directly to Home. 6. Anatomy Full-screen chat UI — message bubbles Seeker messages: right-aligned, Crimson bubble Bot messages: left-aligned, Cloud background, Teal &apos;D+&apos; avatar Persistent input bar at bottom: text field + send icon button On load: welcome message &apos;Hi [Name], I&apos;m here to help you find blood quickly. Accessibility 14.1 Colour &amp; Contrast All text/background combinations must achieve minimum 4.5:1 contrast (WCAG AA). Crimson on white: 4.9:1 ✓. Navy on white: 11.7:1 ✓. White on Crimson: 4.9:1 ✓. Information is never conveyed by colour alone. Status chips use both colour and text. Error states use both red colour and an icon. 14.2 Touch Targets Minimum 48 × 48 dp touch target for every interactive element (Flutter&apos;s Material default is 48 dp). Blood group chips in the picker are 48 dp tall minimum to ensure easy tap in a compact row. OTP digit fields: 56 dp square each — wider than the minimum to avoid mis-taps on adjacent boxes. 14.3 Screen Reader (TalkBack / VoiceOver) All custom widgets must set Semantics(label: &apos;...&apos;) in Flutter. Decorative icons use excludeFromSemantics: true. Image thumbnails (CNIC, selfie) have descriptive labels: e.g., &apos;CNIC front image uploaded successfully&apos;. Status chips read their label + state, not just colour: e.g., &apos;Status: Pending Verification&apos;. BloodGroupChip: &apos;Blood group A positive, selected&apos; when active. 14.4 Text Scaling All sp sizes are relative to system font scale. Test at 1.0×, 1.3×, and 1.5× — layouts must not overflow at 1.5×. Use Flexible and Expanded widgets to allow text to wrap. Avoid fixed-height containers for any text content. 14.5 Keyboard &amp; Focus (Admin Panel) All admin panel inputs are keyboard-navigable with Tab. Focus rings are visible (2 dp Crimson outline). Confirm dialogs are focus-trapped — Tab cycles between action buttons only. 15.
